# 项目页：一份文件，不是一张卡片墙

> 一个项目页只回答四个问题，而且是按这个顺序回答的：
> **这是什么 → 到哪一步了 → 卡在哪 → 谁在做。**

---

## 1. 旧版乱在哪

改之前是 1046 行、7 个组件挤在一个文件里。真正的问题不在代码，在**每块内容的权重都一样**：

| 症状 | 原因 |
| --- | --- |
| 打开后找不到重点 | 封面（大标题 + 编号水印 + 描述 + 状态 + 人数）、4 张指标卡、4 个面板，全是同一级视觉重量 |
| 同一组数字出现三次 | 左栏每行有 `编号 / 3/12 / 5人 / 进度条`，封面又有编号和人数，指标区又有 `3/12` |
| 看不到"卡在哪" | 工作项是最该看的东西，却排在封面和指标卡之后，还只显示 8 行列表 |
| 有个隐藏状态机 | "编辑团队"是一个整页模式：点下去以后多出删除、汇报线、加人三组控件，读者分不清哪次点击是读、哪次是写 |
| 破坏性操作常驻 | 归档按钮固定在页脚，跟正常阅读同屏，且没有二次确认 |
| 规则是开发者概念 | `org_fact` 的 subject/value 两个输入框直接暴露在主区 |
| 页面不能做事 | 唯一的动作是"全部工作项"跳转；想派活必须先回 IM 找人私聊 |
| 归档后项目消失 | `projects.list` 只查 `status='active'`，归档后索引里再也找不到，也没有恢复入口 |

## 2. 新结构

```
┌ 索引 240px ──────────┬ 项目正文 ──────────────────────────────┐
│ 项目 12          [+] │ 工程部 · PRJ-03 · 创建于 2026/9/1       │
│ ● 官网改版      3/12 │ 官网改版                    [派活] [⚙]  │
│   ▓▓▓░░░░░░░░░       │ 把静态页改成可编辑的内容站               │
│ ● 数据管道      8/8  │ ── 进度 25%(3/12) | 在办 3 | 团队 5 | 预算 42% ── │
│   ▓▓▓▓▓▓▓▓▓▓▓▓       │ 看板  待办 4 | 进行中 3 | 待验收 2 | 已验收 1 │
│ ● 移动端        1/6  │ 团队 5人              │ 最近交付 8         │
└──────────────────────┴─────────────────────────────────────────┘
```

### 索引（左栏）
一行只有三件事：**名字、`完成/总数`、一条进度条**。编号、部门、创建时间都归正文，索引里重复一遍就是噪音。

### 封面
一行元信息（部门 · 编号 · 创建日期），标题 + **状态徽章**，一句话描述，右侧两个动作。

状态是 `planning / active / paused / done / archived` 五个真状态，不是标签：徽章点开就是菜单，就地切换；`archived` 是终态，只能从归档动作进入，因此归档项目显示静态徽章、不显示写操作。只有 `active` 能派活——暂停和已完成的项目保留团队，但不再往成员的上下文里灌事实。

### 指标条
四张大卡换成一条四格窄带：交付进度、在办、团队、预算。高度从 ~100px 降到 ~56px，省下来的位置给看板。

### 里程碑
指标条下面一条窄带，回答"这个项目什么时候算完"：

- 已完成 `1 / 4`，每个节点是 `标题 + 可选日期`，完成的划掉、逾期标红。
- 里程碑**不是任务**：没有指派人、预算、验收命令，所以不上看板、不进任务统计。混进 `task` 会让"节点"被算成"工作"。
- 页面只读；增删改在项目设置抽屉里，和团队、约定放在一起。

### 看板（页面主体）
四列：待办 / 进行中 / 待验收 / 已验收。

- `accepted`（负责人已验收）算**进行中**，不算已交付——否则唯一那个进度数字会虚高。
- `rejected` / `failed` 放回待办，但卡片描红并标"需要处理"。
- `cancelled` 不上板，只在标题旁报「另有 N 项已取消」，不让它永久占一个格子。
- 列内排序：优先级 → 最近更新。

### 团队 + 交付物
并排放底部，因为两者回答的其实是同一个问题：这个项目产出了什么、是谁产出的。

## 3. 写操作收进一个抽屉

"编辑团队"这个整页模式取消了。项目页永远是只读的，所有能改的东西在 `项目设置` 抽屉里：

| 分区 | 内容 |
| --- | --- |
| 团队与汇报线 | 成员、项目角色（就地改）、项目内汇报对象、移除、加人 |
| 里程碑 | 增删、改名、改截止日期、勾完成 / 取消完成 |
| 工作约定 | 项目范围内的 `org_fact`，只发给被指派的人 |
| 归档 | 说明 + **二次确认** |

这样读者不需要先判断"我现在在不在编辑模式"，按钮的含义也就是固定的。

## 4. 员工调配在项目页的入口

项目页只做一件事：**把"谁在这个项目里"说清楚**。

| 动作 | 在哪做 |
| --- | --- |
| 加人 / 换项目角色 / 改项目内汇报线 | 项目设置抽屉 |
| 派活（并默认记在这个项目上） | 页面右上角「派活」，复用 `DispatchTaskDialog` |
| 部门归属、岗位、部门汇报线 | 组织页（项目页只读展示 `title · level`） |
| 预算暂停（停的是任职，不是人） | 成本页；项目页在成员名后标"预算暂停" |

`assignment` 本来就是"一人多项目"的矩阵表，项目页是它唯一看得见的读法；部门那一轴不在这里改，也不在这里重复解释。

顺带修掉一个隐患：`DispatchTaskDialog` 原来预填了「写一个 hello world HTTP 服务」这样的示例正文，从项目页派活会直接带着一条假任务。现在初始为空，示例挪进 placeholder。

## 5. 生命周期与索引

- `projects.list()` 默认排除 `archived`，`list({ includeArchived: true })` 才带回来。项目页用后者，把归档项目收进索引底部的「已归档 N 个」折叠区——归档不再等于消失。
- `setStatus` 只接受 `planning / active / paused / done`，拒绝已归档项目。它**不动成员**：暂停或完成只影响状态。
- `archive()` 仍然是单独的显式动作，会解绑全部 assignment，所以不并进状态菜单。
- `activeProjectIdsOf` 只认 `status='active'`：暂停/完成的项目保留团队，但不再向成员的上下文注入项目事实。

## 6. 已知未做

暂无。项目页目前缺的只有一块：**把里程碑和看板的完成度联动**（例如所有里程碑完成时提示把项目切到 `done`）。这属于顺手优化，不构成结构性缺口。
