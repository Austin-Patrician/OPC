# 组织、项目与员工调配：一份信息架构提案

> 一句话：**组织决定"这个人属于谁"，项目决定"这个人现在为谁干活"，工作项决定"他此刻在做什么"。**
> 三件事各有各的表，但界面上现在只在三个互不相干的地方各露出一个角，所以看起来乱。

---

## 1. 现状诊断

代码里已经有三条正交的轴，而且建得很干净（`schema.ts`）：

| 轴 | 表 | 基数 | 生命周期 |
| --- | --- | --- | --- |
| 归属 | `department` + `position` | 一人一个岗位（唯一索引 `idx_pos_employee`） | 长期 |
| 编制 | `job` + `department_job` | 一个岗位全公司共享，各部门各自认领 headcount | 长期 |
| 任职 | `assignment` | 一人多项目（矩阵） | 临时 |
| 工作 | `task` | 挂 `assigneeId` + 可选 `projectGroupId` | 一次性 |
| 钱 | `budget` | 公司 / 部门 / 项目 / 员工 四轴 | 按周期 |

数据层是清楚的。问题全在**界面把这份清楚拆碎了**：

1. **12 条一级导航**，其中 3 条是占位页（`channels` / `deliverables` / `device` 直接指向
   `PlaceholderPage`）。点进去只有一句"即将开放"。这是"页面配置乱"最直接的来源。
2. **`/market` 同时是导航里的一行和 `/org` 里的一个 tab**（`OrgPage` 的 `tab-market` 直接跳
   `#/market`）。同一个概念两个入口，两处都要维护。
3. **派活只有一个入口**：聊天输入框的按钮（`Composer.onOpenDispatch` → `DispatchTaskDialog`）。
   工作项页 `/issues` 是**只读**的——有筛选、批量执行、老板裁决，但没有"新建"。
   所以"怎么给员工派活"这个问题，答案是"先去跟他私聊"。
4. **一个人的全景拼不出来**：`OrgPage` 的员工详情有部门、汇报线、模型、工具策略，但
   **不显示他在哪些项目里**；`ProjectsPage` 的团队编辑能看项目角色，但不显示他的部门；
   聊天里的 `AgentDossierDrawer` 又有第三份（brief、预算）。同一个人四个地方四种片段。
5. **三个页面在数同一批任务**：`/issues`（全公司）、`/projects`（项目内）、`/budget`（花费），
   各自 `work.listTasks(500)` + `listBudgets()`，各自算一遍统计。
6. **设置 11 页塞在 5 组里**，"通用"下面同时躺着外观、公司资料、上下文压缩、运行时——
   前两个是偏好，后两个是基础设施。

> 附带一条：左侧导航 12 行 + 搜索框在 160px 宽的 rail 里，矮窗口下底部那块
> （`SECONDARY_NAV`，含"设置与总控"）会被挤出去。导航条目减到 8 行以内，
> 这个"设置菜单不见了"的问题自然消失；同时给 rail 加 `min-h-0 overflow-y-auto` 兜底。

## 2. 模型：一个主轴，四条边

```
              ┌──────────── 公司 ────────────┐
              │                              │
          部门 (department)              岗位 (job)
              │  position                    │  department_job
              │  一人一岗 / 一条汇报线        │  编制名额
              ▼                              ▼
          ┌─────────── 员工 (employee) ───────────┐
          │        modelRef · 工具策略 · persona   │
          └───────────────┬───────────────────────┘
                          │  assignment（多对多）
                          ▼
                     项目 (project_group)
                          │  task.projectGroupId
                          ▼
                     工作 (task) ──── 预算 (budget)
```

三条规则，写进产品而不是写进文档：

1. **编制是长期的，任职是临时的。** 一个人只能占一个岗位，但可以同时在多个项目里；
   离开项目不等于离职，离职也不该让项目里的历史任务消失（`task.employee_name` 已经是快照）。
2. **派活必须落在一次任职上。** 现在 `task.projectGroupId` 可选，于是会出现"这笔钱没处扣"
   的任务。派活时如果此人不在该项目，先问一句"把他加进项目？"，加完再派。
3. **钱跟着三条轴走，不跟着页面走。** `budget.scope` 已经有 `company | department | project | employee`，
   界面上却只在"成本"页露出；项目页只是读了一个 `scope='project'` 的条。这个不用改数据，改展示。

## 3. 员工调配：一张卡，四个问题

员工详情抽屉（现在 `OrgPage` 里的 `memberDetail`）改成**一个人的全景**，四个分区，都能就地改：

| 分区 | 回答的问题 | 数据 | 动作 |
| --- | --- | --- | --- |
| 归属 | 他在哪个部门、什么岗位、向谁汇报 | `position` | 转岗 / 改汇报线 / 升职 |
| 编制 | 他占的编制名额是谁批的 | `job` + `department_job` | 换岗位（改 jobId） |
| 任职 | 他现在在几个项目里、担任什么角色 | `assignment` | 加入项目 / 换角色 / 移出项目 |
| 产能 | 手上有几件活、今天花了多少 | `task` + `budget` | 派活 / 看工作项 |

### 调配动作矩阵

| 动作 | 语义 | 现在的入口 | 建议 |
| --- | --- | --- | --- |
| 招 | 进公司（成为 `employee`） | 组织页"自定义招聘" / 人才市场导入 | 保留 |
| 落岗 | 进部门、占编制、定汇报线 | 组织页拖拽（`BoardView`） | 保留，员工详情也能做 |
| 上项目 | 进项目编制、定项目角色 | 项目页"编辑团队" | **双向**：员工详情加"加入项目"，项目页加"从部门挑人" |
| 派活 | 给一件可验收的活 | **只有聊天框** | 加三个入口：工作台 / 员工详情 / 项目页，共用 `DispatchTaskDialog` |
| 调岗 | 换部门 | 组织页拖拽 | 保留 |
| 停 | 预算硬停（停的是任职，不是人） | 成本页 | 保留；员工详情只读展示 `pauseReason` |
| 走 | 离职（`terminated`，不硬删） | 组织页 personnel | 保留 |

**关键新增：项目占用视图。** 组织页看板卡片现在显示 `activeTasks`，加上"在 N 个项目"，
老板一眼能看出谁被摊薄了。数据现成（`assignment` 按 `status='active'` 聚合），不用改表。

## 4. 页面配置：12 条导航 → 8 条

每个页面只承诺一件事：

| # | 页面 | 承诺 | 变化 |
| --- | --- | --- | --- |
| 1 | 对话 `/chat` | 我在跟谁说话 | 不变 |
| 2 | 工作台 `/issues` | 现在有什么活、卡在哪 | 改名（工作项→工作台），**加"派活"按钮** |
| 3 | 组织 `/org` | 谁在公司、归谁管 | **吸收人才市场**（内部 tab，不再单独一行） |
| 4 | 项目 `/projects` | 哪些项目在跑、谁在做 | 加"从部门挑人" |
| 5 | 成本 `/budget` | 钱花在哪 | 不变 |
| 6 | 能力 `/skills` | 模型和 Agent 能用什么 | 不变 |
| — | 通知 `/notifications` | 什么需要我处理 | 次级 |
| — | 设置 `/settings` | 装什么、连什么 | 次级 |

**删掉的四个入口**：

- `渠道 /channels` — 未实现。将来它就是对话列表的一个筛选维度（`ConversationKind = 'channel'`），
  不该占一级导航。
- `交付物 /deliverables` — 未实现。交付物是 `task.artifacts` 的投影，归属项目页的"交付物"面板。
- `设备 /device` — 未实现，而且和当前桌面端无关。真要留，进设置。
- `人才市场 /market` — 概念正确但位置错误。"待安置员工"是组织的一层，不是并行的第二套 HR。

### 设置页重排（11 页，5 组 → 4 组）

| 组 | 页 |
| --- | --- |
| 通用 | 外观、公司资料 |
| 运行 | 运行时、上下文压缩、网络 |
| 模型 | LLM、Image、Voice、Decision |
| 系统 | 自检、关于 |

变化只在分组：`compaction` / `runtime` 从"通用"挪到"运行"，`network` 从独立组并入"运行"。
理由：外观和公司资料是"这个应用长什么样"，运行时和压缩是"它怎么跑"，两类问题的排查路径不同。

## 5. 落地顺序

### P0 — 只动导航和页面骨架（约半天，风险最低）

1. `NavRail.tsx`：`PRIMARY_NAV` 9 → 6，`SECONDARY_NAV` 保留 3（通知/设备暂留或删，见下）；
   rail 加 `min-h-0 overflow-y-auto`，解决矮窗口下底部菜单被挤出。
2. `App.tsx`：`/channels` `/deliverables` `/device` 路由保留（深链接不 404），但从导航移除。
3. `OrgPage.tsx`：`tab-market` 从"跳 `#/market`"改成内部 tab（复用 `MarketPage` 内容）；
   `/market` 路由保留为重定向。
4. `SettingsShell.tsx`：`groups` 重排为 4 组。
5. i18n：`nav.*` 标签调整，`zh-CN` / `en-US` 同步。

**做完这一步，"页面乱"和"设置菜单消失"两个问题同时结束。**

### P1 — 统一调配（1～2 天）

1. 新增 `EmployeeDeployment` 面板（`features/employee-stack/ui/` 旁边），四分区 + 调配动作。
   复用现有 IPC：`org.personnel` / `projects.assign` / `projects.removeMember` / `projects.setReportsTo`。
2. `DispatchTaskDialog` 三处复用：`IssueListPage` 加"派活"、员工详情加"派活"、`ProjectsPage` 加"派活"
   （默认 `projectGroupId` 已填）。
3. 派活前校验：assignee 不在项目 → 提示并就地 `projects.assign`。

### P2 — 产能与成本视图（视需要）

1. 组织看板卡片加"在 N 个项目"。
2. 项目页的预算条改成读 `budget.scope='project'` 的完整状态（现在只读了一个比率）。
3. `/issues` 与 `/projects` 的任务统计抽成一个纯函数（现在各算一遍）。

## 6. 不做的事

- **不合并 `/issues` 和 `/projects`。** 它们回答不同问题："公司现在有什么活" vs "这个项目做到哪了"。
  合并会得到一个既不能全局扫、也不能聚焦的单页。
- **不给 `task` 加强制 `projectGroupId`。** 老板临时让人干件小事（"查一下这个报错"）不该先建项目。
  只在派活时**提示**，不阻断。
- **不引入"团队"作为第四种组织单元。** `assignment` 已经是项目内编制，再加一层只会让汇报线更难追。
