# 没有组织结构，没有员工

> 上游：`01-core.md` §10 / `02-residue.md`。
> 这一份不再是"清残留"，是把 `employee` 和 `department` 从模型里拿掉。
>
> **结论先说**：`orgService`（3,459 行）不是最难的地方。最难的是 **IM** ——
> 现在"我在和谁说话"的答案是"某个人"，没有员工之后这个答案必须换掉。

---

## 1. `employee` 在运行时里的六条依赖

| # | 依赖 | 现在在哪 | 换成什么 | 规模 |
|---|---|---|---|---|
| 1 | 工具注册表的主体 | `buildRegistry(employeeId)` | `buildRegistry(worker)` ✅ 已做 | 中 |
| 2 | 工具策略 | `org.toolPolicyOf()` | worker 的模板默认（本来也没有 UI 能改，等同空） | 小 |
| 3 | 通讯工具（同事） | `comm` 工具的 `colleagues` 来自 `org.list()` | 没有同事 → 工具不装 | 小 |
| 4 | 记忆分区 | `employeeId` + 部门 / 项目 scope | 挂在 thread 上 | 中 |
| 5 | **IM 的对话对象** | "和某人开对话"，成员列表来自 `org` | 只剩「助手」+「工作线」 | **大（产品决定）** |
| 6 | 预算轴 | `employee` / `department` | `thread` / `global` | 中 |

1–3 是一组（工具注册表），4 和 6 各自独立，**5 是前置**：它决定 `agentsFromOrg`
还能不能存在，而 chat / comm / 能力页全都吃它。

---

## 2. 建议顺序

```
① 工具注册表的主体改成 worker     ✅ 已做（`work/registrySubject.ts`）
② 预算回到两轴（thread / global）
③ 记忆改成 thread scope
④ IM 收敛成「助手」+「工作线」    ← 需要拍一次产品决定
⑤ 删 org/ + 12 张表 + employee
```

②③ 可以在 ④ 之前做，但 ⑤ 必须最后：只要 IM 还在按人列会话，
`employee` 就不能删。

---

## 3. 第 ④ 步要拍的那一件事

现在 IM 的左栏是「会话列表」，每个会话对应一个人或一个部门群。没有员工之后，
还剩哪些会话？

| 方案 | 左栏长什么样 | 代价 |
|---|---|---|
| **A**（建议） | 「助手」一个固定会话 + 每条工作线一个会话 | 老板的心智变成"跟一件事打交道"，和注意力队列一致；要新增"按 thread 开会话" |
| B | 只保留「助手」一个会话 | 最简单，但工作线的过程就看不到了，只能看汇报 |
| C | 每个 worker 一个会话 | worker 是临时的，列表会不停变动，最差 |

建议 **A**：它和首页（注意力队列）是同一个心智模型 —— 老板跟进的是事，不是人。

---

## 4. 判断口径（沿用 `02-residue.md`）

> 删掉之后，用户能做的动作变少了吗？

拿它衡量这三条：

- 「和某人开对话」→ 换成「和助手说话」，动作没少，**换**
- 「按部门建群」→ 已经删了，没人少做过什么，**删**
- 「部门预算」→ 没有部门可管，**删**
