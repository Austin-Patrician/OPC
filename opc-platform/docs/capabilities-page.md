# 技能与工具页（四个 tab）

> 页面只有一个承诺：**它列出来的就是运行时真的装进去的东西**。所以四个 tab 不是四个
> 营销分区，而是同一份注册表快照的四种读法。

---

## 1. 为什么分 tab

原来是一整列长页：能力总览 → 本机 Pi 扩展 → 本机技能 → 扩展与工具 → 按 Agent 查看。
问题不在长度，而在**它把两种问题混在了一起**：

| 问题 | 需要的数据形状 | 现在的归属 |
| --- | --- | --- |
| 装了哪些扩展？ | 一行一个扩展，带安装人数 | 扩展 |
| 模型能调用什么？ | 一行一个工具，带可调用人数 | 工具 |
| 有哪些说明书？ | 一行一个 SKILL.md | 技能 |
| 有没有接外部服务？ | 一行一个 MCP server | MCP |

一份数据、两种形状，页面上却各写了一遍，于是"扩展里的工具"和"按 Agent 看"里的工具
迟早会对不上。分 tab 之后，**扩展 tab 只数工具不列工具**，工具 tab 只列工具不分扩展细节，
两边都由 `model/grouping.ts` 的同一组纯函数算出来。

## 2. 四个 tab

页头下面直接是 tab，**没有"能力总览"卡片**：四个数字（Agent / 扩展 / 工具 / 档案标签）原本要占一整块，
而 tab 徽标已经把前三个数字放在了拇指够得着的地方，再画一遍只是把正文往下推。读取时间挪到了页头右侧
（「读取于 15:31」），刷新按钮旁边——它本来就是"这份数据有多新"的注解，不是一张卡片。

### 扩展

两段：**本机 Pi 扩展**（磁盘上发现的，带信任开关）和**内置扩展**（OPC 自己的
`opc.work` / `coding-tools` / `opc.sandbox` …）。

内置扩展行只显示名字、`opc.*` 标识、安装人数和"几个工具 / 几个钩子 / 几段提示词"，
**不列工具**——那是工具 tab 的事。徽标里的数字是安装该扩展的 Agent 人数。

### 工具

按提供它的扩展分组，每行一个工具：名字、说明、能调用它的 Agent 人数。底部是
**按 Agent 查看**（展开一个人，看他自己的扩展 / 档案技能标签 / 可调用工具），也就是同一份
数据的反向索引。

一个工具只会出现一次，哪怕 7 个 Agent 都装了它——重复 7 遍是噪音，人数才是信息。

### 技能

`~/.agents/skills` 的 SKILL.md，一行一个，带作用域、prompt 成本估算、自带文件数。
纯文本，不需要信任，所以这里是普通开关而不是信任框。详见 `docs/skills.md`。

### MCP（占位）

OPC 还没有 MCP 客户端。这一页**明确说没有**，并列出接上它至少需要什么
（stdio/SSE 客户端、tools 翻译成 pi-durable 工具、沿用信任与员工级开关）。

写占位而不是写"即将推出"，是因为整个页面的价值就在于不撒谎：一个空的假列表
会让人以为"接好了但没工具"，而事实是"根本还没接"。

## 3. tab 存在 URL 里

`#/skills?tab=tools`。理由很实际：

- 刷新 / 点「刷新」按钮不会把用户弹回第一个 tab；
- 想让人看某一页，直接把链接发过去；
- 第一个 tab 不带参数（`#/skills`），保持旧链接可用。

`useSearchParams` 的 `replace: true`，所以点 tab 不会在浏览历史里堆一串记录。

## 5. 滚动条

页面正文（`CapabilitiesPage` 以及预算 / 市场 / 通知 / 项目 / 设置这些同构页面）都用 `.page-scroll`。
原因不是审美，而是一个真实的 bug：

`styles/index.css` 的全局规则同时写了 `scrollbar-width: thin` 和 `::-webkit-scrollbar { width: 5px }`。
**Chromium 里前者会让后者失效**——实测滚动条是 10px 的平台样式（滑块内缩 2px），
所以看起来"离右边缘很远"，和设计稿的 5px 细条对不上。

`.page-scroll` 在这类容器上把两个标准属性重置成 `auto`，把控制权交回伪元素，于是：

| | 改前 | 改后 |
| --- | --- | --- |
| 滚动条宽度 | 10px | 5px |
| 滑块到卡片右边框 | 卡片内缩 ~2px + 轨道留白 | 紧贴（1px 边框） |

只作用在页面级滚动容器上：聊天列表、会话列表和菜单保持平台滚动条（macOS 上它是 overlay，不占位）。

## 6. 结构

```
CapabilitiesPage.tsx        取数、开关、tab 状态
  model/grouping.ts         纯聚合：groupExtensions / toToolGroups / toolAgentCounts
  ExternalExtensionsSection 本机 Pi 扩展 + 信任框
  ToolsSection              可调用工具 + 按 Agent 查看
  SkillsSection             本机技能
  McpSection                占位
```

`grouping.ts` 有单测（7 个），因为"扩展 tab 说 7 人、工具 tab 说 6 人"这种 bug
在界面上极难发现，在纯函数里一测就露。
